# ADR-0018：第一次啟動時讓使用者選資料位置

- 狀態：**已接受**
- 日期：2026-10-10
- 取代：[ADR-0004](ADR-0004-data-program-separation.md) 裡「帳務資料放在專案資料夾之外」**對下載使用者**的那一部分。
  這個 repo 的開發者本機不變：資料仍在專案外的資料根，由指標檔指定（CONVENTIONS §11）。

## 背景

使用者希望「從 GitHub 下載來用的人，資料放在專案內比較方便」。在這之前，沒設定過路徑的人資料一律放在
`%LOCALAPPDATA%\TagCor\TagCorLedger\`：預設就是隱藏資料夾，使用者不知道帳本在哪，也沒辦法把整個程式
資料夾帶走。ADR-0004 這樣做的理由是「分開放讓個人財務資料外洩在結構上不可能發生，而不是靠 `.gitignore`
的正確性」—— 對開發者自己那一份 repo 仍然成立；但下載使用者大多不會 commit，對他們而言那個保證的代價
（找不到資料、搬不走）比較實際。

比較過三個做法：

| | A. 維持 AppData | B. 預設改到專案內 | C. 第一次啟動時問 |
|---|---|---|---|
| 找得到資料 | 藏在 AppData | 就在程式資料夾裡 | 自己選的，知道在哪 |
| 換電腦 | 程式與資料分開搬 | 整個資料夾帶走 | 選專案內就同 B |
| 下載新版 ZIP 更新 | 資料不受影響 | **新資料夾是空帳本**，舊資料夾一刪就沒了 | 選專案內也有這個風險，但選的時候看得到提醒 |
| 專案放在 OneDrive 同步的桌面或文件 | 不受影響 | SQLite 被雲端同步有損毀風險 | 選專案內就同 B |
| 推上 GitHub 外洩 | 預設下不會 | 靠 `.gitignore` 忽略整個資料夾 | 同 B |
| 開發者本機的指標檔遺失時 | AppData 出現一本空帳本 | 專案資料夾裡出現一本空帳本 | 跳出詢問，看得出不對勁 |

使用者選 **C**，並決定：子資料夾叫 `userdata`、預選程式資料夾、要有第三個選項「其他位置…」。

## 決定

**第一次啟動時跳出對話框，三選一**（`ui/first_run_dialog.py`）：

1. **放在程式資料夾裡**（預選）—— `<程式資料夾>\userdata`。**不寫指標檔**。
2. **放在這台電腦的使用者資料夾** —— `%LOCALAPPDATA%\TagCor\TagCorLedger`。不寫指標檔。
3. **其他位置…** —— 使用者挑資料夾；裡面已經有帳本就接上它，沒有就新建。**寫指標檔**。

**每次啟動都照同樣四步找**（`app/data_location.py`）：指標檔 → `userdata` 裡的帳本 → 使用者資料夾裡的帳本 →
都沒有才問。有指標檔就停在第一步，跟以前一模一樣。

- **「問過了沒」不另外記，看帳本檔在不在。** 按「確定」當場就建出帳本，下一次第二或第三步就找到它。
  旗標是第二份會跟檔案對不上的事實；而且放在 AppData 的話，把程式資料夾帶到別台電腦又會被問一次。
- **看帳本檔，不看資料夾**：啟動器的預檢在使用者選之前就會建 `logs\`。
- **程式資料夾那一種不寫指標檔**：指標檔記的是絕對路徑，資料夾一搬就指錯地方，而且會在舊位置默默建一本空帳本。
  每次從程式自己的位置（`program_root()`）往下找，搬到哪裡都對。
- **`userdata` 整個在 `.gitignore` 裡**，用 `git check-ignore` 守著：匯出的交易 CSV 與備份的 manifest 都不是
  `*.sqlite3`。「其他位置…」不能挑在程式資料夾裡面，理由相同。
- **舊使用者不會被問**：AppData 已經有帳本的人，第三步就找到它。

## 被否決的替代方案

- **A. 維持 AppData**：達不到「找得到、帶得走」。
- **B. 預設改到專案內、不問**：下載新版 ZIP 解到新資料夾時，打開是一本空帳本，看起來像資料全部消失 ——
  這正是這個專案一直在防的事（CLAUDE.md「搬移資料的順序不可調換」那一條的同一種症狀）。而且是在使用者
  不知情的情況下發生。
- **程式資料夾也寫指標檔（絕對路徑）**：實作最單純，但搬資料夾就斷，斷的方式是在舊路徑建一本空帳本。
- **用旗標記「問過了」**：見「決定」。

## 後果

- **對開發者本機沒有任何影響**：有指標檔，第一步就決定了。
- **`.gitignore` 從「保險」變成「這個選項成立的前提」** —— 所以它有測試，不只是一行設定。
- 選了程式資料夾的人，使用者資料夾裡仍會有啟動器預檢留下的 `logs\` 與 `tmp\`（選之前的那一次）。沒有帳本。
- **更新程式要帶走 `userdata`**：用 `git pull` 更新的不受影響（被忽略的檔案不會動），下載 ZIP 的要自己搬。
  對話框與 README 都寫了。
- 「指標檔還在、但它指的帳本不見了」維持原本的行為（在原位置建一本空帳本），不在這份 ADR 的範圍。
- 啟動器的預檢在「還沒選」時拿到的是暫時的路徑（使用者資料夾），所以 `--json` 多了 `data_location`；
  對話框一顯示就寫啟動器在等的標記檔。

## 什麼情況下這份 ADR 該被推翻

- 開始提供安裝程式（裝進 `Program Files` 這種寫不進去的地方）：程式資料夾那個選項就不成立了，
  `program_root()` 會回 `None`，對話框已經會把它停用 —— 但預選與說明要重新想。
- 發現下載使用者實際上會 commit 自己的副本：`userdata` 被忽略仍然擋得住帳本，但要重新評估 ADR-0004 的保證。
