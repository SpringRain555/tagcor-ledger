# ADR-0015：餘額盤點的「刪除」改成真的移除

- 狀態：**已接受**
- 日期：2026-10-05
- 取代：[REQ-0003](../requirements/REQ-0003-balance-snapshots.md) 原本的「刪除的盤點（`voided`，紀錄保留）」。
  **交易的刪除不受影響**，仍然是 `void`（[state-machines.md](../architecture/state-machines.md) §1）。

## 背景

盤點的「刪除」一直是 `void`：那一列標成 `voided`、不再當基準點，紀錄留著，在「列表狀態」
選「已刪除」看得到，**不可復原**。這套做法是照搬交易的 —— 交易那邊的理由是：

> 復原會讓「這筆到底有沒有計入」的歷史變得無法追溯。

使用者問：「餘額盤點為何不能將盤點紀錄完整刪除？」查下去，**那個理由在盤點身上不成立**：

| | 交易 | 盤點 |
|---|---|---|
| 是錢的進出嗎 | 是。它改變餘額 | **不是**。它只記「那一刻數出來多少」 |
| 有東西指向它嗎 | 有：posting、`replaces_transaction_id`、定存事件的 `transaction_id` | **沒有**。差額每次現算，上一筆是查出來的 |
| 留著 `voided` 換到什麼 | 「這筆曾經計入過」的歷史 | 什麼都沒有 —— 它不可復原，也不參與任何計算 |

而留著是有代價的，而且查到一個真的缺陷：

- **已刪除的盤點擋住帳戶刪除。** `delete_account()` 的引用檢查是
  `balance_snapshots WHERE account_id = ?`，**不看狀態**。把一個帳戶的盤點全部刪掉，
  帳戶照樣刪不掉，訊息還說「這個帳戶已經有交易紀錄」—— 那個帳戶一筆交易也沒有。
  這跟 v0.22.0 修掉的「封存的模板擋住帳戶刪除」是同一個形狀：**看不見但還在**。
- 「列表狀態」下拉多佔表單一列，而它唯一的用途是去看一堆救不回來的列。

## 決定

**盤點的「刪除」是真的 `DELETE`。**

| 層 | 改了什麼 |
|---|---|
| store | `void_balance_snapshot()` → `delete_balance_snapshot()`；稽核表留一列 `balance_snapshot.delete`，只記帳戶與日期、**不記金額** |
| migration | `migrate_v12` 刪掉既有的 `voided` 盤點。它們本來就是使用者刪掉的，不參與任何差額計算 |
| application／controller | `void()` → `delete()`；`BalanceSnapshotFilter` 拿掉 `status`；錯誤碼 `BALANCE_SNAPSHOT_STATUS_FILTER_INVALID` 退役 |
| UI | 「列表狀態」下拉拿掉；確認框講「刪掉之後就找不回來」，以及後面那次盤點的差額會改拿再前一次重算 |
| CSV | 「狀態」欄拿掉（永遠是「有效」） |

`status` 欄與它的 `CHECK` **留著**：拿掉要重建整張表，換到的只是少一個永遠是 `active` 的欄位。
查詢裡的 `status = 'active'` 也留著 —— 沒有帳戶篩選時（匯出 CSV），那是讓
`(status, observed_at)` 索引用得上的條件。

## 被否決的替代方案

| 方案 | 為什麼否決 |
|---|---|
| **維持 `void`，只修「擋住帳戶刪除」** | 修得掉缺陷，但留下一個沒有用途的狀態：救不回來、不參與計算，只佔一個篩選 |
| **`void` 之後再提供「永久刪除」** | 兩段式刪除的價值在第一段可以反悔，而 `void` 本來就不可復原。第二段只是多按一次 |
| **舊的 `voided` 留著讓使用者逐筆清** | 它們已經被刪過一次了。要使用者再刪一次，等於讓舊做法的代價由使用者付 |
| **連稽核表裡這些盤點的建立紀錄一起刪** | 稽核表是「誰在什麼時候做了什麼」的唯一紀錄，只有 `stores/base.py` 一個寫入點、只增不刪。畫面上看不到它 |

## 後果

- **好的**：盤點清單只有一種列；帳戶刪不掉時不會再是因為一筆看不見的盤點；表單少一列。
- **壞的**：刪錯了就沒了。確認框會把日期念出來，而盤點本身重打一次只要十秒 ——
  它不像交易那樣會牽動別的東西。
- **稽核表仍然記得那筆盤點的建立與修改**（`balance_snapshot.create`／`.update` 的 details 帶金額）。
  畫面上看不到它；要連那些都抹掉，是另一個決定。
- **交易的「刪除」沒有跟著改。** 兩個「刪除」從這一版起是兩件事：交易是 `void`（紀錄留著），
  盤點與名冊是真的移除。`glossary.md` §操作 寫明。
- migration 不能 un-delete：要改回來，是新增 migration 與新的 ADR，不是改 `migrate_v12`。

## 什麼情況下這份 ADR 該被推翻

**有東西開始指向盤點。** 例如 [REQ-0010](../requirements/REQ-0010-reconciliation-gap.md) 的
「未解釋差額轉成調整交易」真的做出來、而那筆交易記得自己是從哪一次盤點來的 ——
那時刪掉盤點就會讓別的東西失去來源，盤點才需要交易那種「紀錄留著」的刪除。
