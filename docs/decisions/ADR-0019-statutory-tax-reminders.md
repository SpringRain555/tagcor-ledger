# ADR-0019：稅務提醒依法定期間觸發，由帳本事實結案

- 狀態：**已接受**
- 日期：2026-11-09
- 取代：無。**與 [ADR-0014](ADR-0014-drop-daily-snapshot-reminder.md) 的關係是「符合它的推翻條件」，不是推翻它**；
  與 [ADR-0011](ADR-0011-drop-recurring-schedules.md) 同向（不產生草稿）。
- 規格：[REQ-0011](../requirements/REQ-0011-tax-reminders-and-estimate.md) §提醒、§資料新鮮度

## 背景

使用者要稅務「有實際作用」：繳稅期間到了，開程式就知道要不要處理。這需要**依日期觸發的提醒** ——
而這個專案正好有兩份 ADR 把依日曆觸發的東西拿掉了：

- ADR-0011 拿掉定期收支：「定期收支省的不是輸入，是『想起來』—— 而『想起來』已經由簡訊負責了。」
- ADR-0014 拿掉「今天還沒盤點」：「它的觸發條件是日曆，不是事實。」並寫明推翻條件：
  「**盤點的節奏變成規律的** …… 那時日曆才真的對得上事實。判準是**節奏，不是頻率**。」

所以要先回答 ADR-0014 自己問的那一句：**這則提醒的觸發條件是日曆還是事實？**

## 判斷：法定期間是外部的節奏

綜所稅 5 月申報、房屋稅 5 月、地價稅 11 月、牌照稅 4 月、燃料費 7 月 —— 這些日期**不是使用者自己的習慣**，
是法律與主管機關訂的，而且錯過有後果（滯納金、補稅）。這正是 ADR-0014 說的「日曆對得上事實」：

| | 「今天還沒盤點」（ADR-0014 拿掉的） | 稅務期間（這一份要加的） |
|---|---|---|
| 誰訂的日期 | 沒有人，程式自己拿「今天」比 | 法律與主管機關公告 |
| 跳的頻率 | 每天 | 每個稅目一年一次、前後約七週 |
| 不處理會怎樣 | 什麼都不會發生 | 滯納金、補稅 |
| 怎麼結束 | 只有盤點一途 | **帳上記了那一筆繳款**、手動標記、或過了期限 30 天 |

ADR-0011 擔心的「想起來由簡訊負責」也不成立：稅單是紙本郵寄或電子通知，**期間開始時沒有人提醒你**；
而綜所稅申報根本沒有稅單。

## 決定

1. **五個稅目依法定期間提醒**：期間開始前 14 天「即將開始」、期間中、截止後 30 天內「已過期限」。
   期間的日期來自 `reference/tax/dataset.json`（有公告用公告，沒有就用法定典型期間並標「預估」）。
2. **由帳本事實結案**：期間內記了一筆支出、其類別對應到那個稅目 → 那則提醒自己消失。
   這延續 ADR-0014 的精神：留下來的提醒，觸發與結束都要對得上事實。手動「已處理／本年不適用」是補充，只管當年。
3. **狀態每次現算，只存標記與開關**：沒有排程、沒有產生出來的列、不需要啟動時跑任何東西 ——
   刪掉一筆繳款，提醒就回來；改了 dataset，下一次開程式就是新的日期。
4. **不產生草稿**：提醒只是一行字與一顆「查看」，不碰待確認（ADR-0011 的取捨不變：稅額每年不同、要照稅單填）。
5. **預設不猜**：綜所稅預設開；房屋稅、地價稅、牌照稅、燃料費預設「未設定」，總覽用一列請使用者決定一次。
   App 不知道使用者有沒有房、車 —— 預設開的話，沒有土地的人每年 11 月都會看到一則與他無關的提醒，那正是 ADR-0014 要避免的噪音。
6. **總覽有上限**：最多 3 列提醒＋1 列狀態，超過的合併成「另有 N 件」；沒事整列隱藏。
7. **資料過期也是事實觸發**：缺年度參數、到了 dataset 自己寫的 `next_review_on`、報稅季前法規庫還沒複查 —— 都是
   「資料與世界對不上」，不是「今天的日期變了」。這也補上 REQ-0008 一直沒做的「5 月報稅季前提示全面複查」。

## 被否決的替代方案

| 方案 | 為什麼否決 |
|---|---|
| **啟動時跳出對話框** | 這個專案的提醒一律放在頁面上（`overview.py` 的頁面說明第 3 點）；對話框會擋住每一次開程式，UI 測試也會把沒預期的對話框當失敗 |
| **Windows 通知／排程工作** | 要常駐或註冊系統排程，App 是「使用者自己開、自己關」（CONVENTIONS §16）；而且程式沒開的時候本來就不該替使用者做事 |
| **匯出 .ics 讓行事曆提醒** | 期間每年變、還會順延，匯出的檔案不會跟著更新；也做不到「記了繳款就消失」 |
| **把提醒做成待確認草稿** | 等於把 ADR-0011 拿掉的定期收支加回來，而且金額每年不同、草稿上的數字一定是錯的 |
| **五個稅目全部預設開** | 見決定第 5 點 |
| **只靠手動標記結案** | 使用者記了繳款還要再按一次「已處理」，是同一件事做兩次；帳本已經知道答案 |

## 後果

- **好的**：總覽第一次有「會過期的事」的提醒，而且結束條件是帳本裡的事實；不需要任何背景工作或排程表。
- **壞的**：要靠使用者把「房屋稅」這類支出類別對應到稅目，PAID 才會自動成立；沒對應的話要手動標記。
  資料（期間）會過期，所以要有 §資料新鮮度 那一套與 LLM session 的更新手冊。
- 地價稅（11/1–11/30）在這份 ADR 生效時正在期間內 —— 第一版上線就會碰到「未設定」那一列，這是預期的。
- 測試要能不隨季節變：日期邏輯一律在 UI 以下以 `today=` 測，UI 測試用固定的假資料（REQ-0011 §驗收）。

## 什麼情況下這份 ADR 該被推翻

- 使用者改用別的提醒管道（例如稅務機關的電子通知已經夠用），總覽的稅務列變成重複的噪音 ——
  那時把預設改成全部未設定，或整組拿掉，並新增一份 ADR。
- 出現「不是法定期間」的稅務提醒需求（例如「每月提醒記一下獎學金」）—— 那是依日曆觸發的提醒，
  **不在這份 ADR 的範圍**，要回到 ADR-0014 的判準重新問一次。
