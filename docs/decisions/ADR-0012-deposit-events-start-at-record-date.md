# ADR-0012：定存的待確認項目從「建檔那天」開始，不補歷史

- 狀態：**已接受**
- 日期：2026-08-23
- 取代：無。**與 [ADR-0006](ADR-0006-manual-entry-only.md) 同向** —— 那份決定
  「每一筆都手動輸入」，這一份決定「程式也不替你補輸入以前的每一筆」。

## 背景

使用者拿著郵局的定期儲金存單建第一份合約。存單上印著：

```
存款日期：112 年 11 月 15 日      到期日期：113 年 11 月 15 日      期限：1 年 00 月
到期及轉存方式：☑ 3. 本金無限次數自動轉期續存，利息轉存帳戶
```

他照抄，把起存日填成那一期的日期。而他的郵局帳戶是**今天**才建的，期初餘額填的
是存摺上當下的數字。

問題：`generate_due()` 只看兩件事 —— `term.maturity_date <= 今天 + 7 天`，
以及 `monthly_dates(起存日, 到期日, 今天)`。**帳戶什麼時候建的、期初餘額是多少，
它一概不知道。** 於是：

| 計息方式 | 起存日填 2025-02-15，今天 2026-08-23 |
|---|---|
| 整存整付 | **1 筆**：一件 2026-02-15 到期的項目 |
| 存本取息 | **13 筆**：12 筆領息 ＋ 1 筆到期，日期全部在過去 |
| 零存整付 | **13 筆**：12 筆存入 ＋ 1 筆到期，日期全部在過去 |

那些利息在他開始記帳之前就已經進了郵局帳戶 —— **也就是已經含在他今天填的期初
餘額裡**。全部確認下去就是把同一筆錢記第二次。

`REQ-0007` §既有定存的上線方式 與 go-live runbook 早就給了正確填法（起存日填
**目前存續中那一期**的 2026-02-15，因為自動轉期續存已經滾過兩輪），但那是一條
**只寫在文件裡的規則**，程式沒有任何一處在幫忙。

## 決定

**`deposit_contracts.recorded_on`（把這份合約記進帳本的那一天）是產生待確認項目的
下界。** 建檔日之前到期的事件一律不產生。

```python
floor = contract.recorded_on
if due >= floor and self.store.add_event(...):   # 每月領息與每月存入
if floor <= term.maturity_date <= horizon:       # 到期
```

配套三件：

1. **schema v9** 新增 `recorded_on TEXT NOT NULL DEFAULT ''`，既有合約用
   `created_at` 的日期部分回填。**回填得對很重要** —— 留空的話它比任何 ISO 日期都
   小，等於沒有下界。
2. **新增合約的對話框當場提醒。** 填的那一期已經到期時，說出它什麼時候到期、
   為什麼不會產生項目；選的是「無限次數自動轉期續存」時再算出目前存續中那一期的
   起存日，給一顆按鈕直接套用。
   （⚠ **這一點在同一天就被下面的「第二次修正」取代了** —— 欄位改成問存單上那一天，
   警告與那顆按鈕一起拿掉。）
3. **`recorded_on` 可以由呼叫端指定**，預設今天。

### 為什麼不直接讀 `created_at`

讀得到，第一版也真的是這樣寫的。但 `created_at` 是一個**技術性的稽核時間戳**，
而這裡要的是一條**業務規則**。兩件事綁在同一欄的代價立刻就出現了：
`generate_due(today=...)` 特意讓測試控制「今天」，而下界卻黏在真實的牆上時鐘 ——
於是十幾條原本有意義的測試同時變成「什麼都沒產生也算通過」。

那不只是測試的不方便。**一個測不到的規則就是一個沒有人在看的規則**，而這條規則
決定的是「使用者會不會被灌一堆重複的項目」。

## 被否決的替代方案

| 方案 | 為什麼否決 |
|---|---|
| **不擋，只在建檔時警告** | 警告看過就沒了，而那 13 筆會一直躺在待確認頁。使用者要一筆一筆略過 —— 而到期那一筆還略過不掉 |
| **下界訂在「今天」（產生時不看過去）** | 會漏掉真正該提醒的事：程式一個月沒開，那個月到期的定存就永遠不會出現 |
| **下界訂在「期」的建檔日而不是合約的** | 續存產生的新一期 `created_at` 是確認的那一刻。使用者晚三個月才確認到期的話，新一期那三個月的領息會被自己的下界擋掉 —— 而那三筆是真的該記的 |
| **建檔時自動把起存日往前滾** | 那是替使用者決定他手上那張存單講的是哪一期。**續存類**滾得出唯一答案，**不自動轉存**根本沒有下一期 —— 一個會在一半情況下捏造事實的自動化。（⚠ **這一格的判斷在「第二次修正」裡被推翻了一半**：滾期本身沒問題，問題在於當時的欄位問的是「目前那一期」而不是「存單上那一天」。欄位問對之後，不續存的那一半根本不會滾 —— `current_term()` 直接回傳原值。）|

## 後果

- **好的**：照存單抄起存日不再灌爆待確認頁，而且對話框當場說得出正確的那一期。
- **壞的**：定存**昨天**才到期、今天才想起來要記的話，程式不會產生那一筆。
  這是刻意的 —— 那筆錢已經在期初餘額裡，要記就到「記帳」頁自己記一筆，
  跟任何一筆開帳前的歷史一樣（`REQ-0007` 對二月那筆活儲→定存轉帳的處置相同）。
- **中性**：`recorded_on` 之後可能會有第二個用途（例如「這份合約是什麼時候開始
  追蹤的」顯示在畫面上）。目前只有這一個。

## 2026-08-23 當天的第二次修正：欄位問錯了東西

上面那個「配套第 2 點」（對話框提醒＋一顆改日期的按鈕）交出去之後，使用者問：

> 我目前定存的方式是無限續期的⋯⋯當初填寫的契約是 112/11/15（**我想記錄的日期，
> 就是這個起始日期**），目前建立起來的只會有一筆 112/11/15–113/11/15 的項目，
> 我的預期是直接顯示當前期間的 114/11/15–115/11/15，會建議這樣顯示嗎？

那個問題指出了第一版沒看見的事：**問題不在使用者填錯，在欄位問錯了東西。**

第一版的「起存日」要填的是**目前存續中那一期**的起存日 —— 而使用者手上那張紙印的
是 112/11/15。於是那個欄位的正確值不是他知道的任何一個數字，得靠一段警告加一顆
按鈕才問得出來。**一個需要警告才填得對的欄位，是欄位的問題。**

### 決定（v0.24.0，schema v10）

`deposit_contracts.opened_on` —— **存單上首次存入的那一天**。

- 對話框問的是「首次起存日」，也就是紙上那個數字。
- `domain.deposits.current_term()` 算出該建立哪一期，**同時算出期序** ——
  上面那個例子建立的是 2026-02-15 – 2027-02-15，而它是**第 3 期**。
- 對話框永遠說出結果（「目前存續中的是第 3 期：2026/02/15 – 2027/02/15」），
  不只在填錯的時候。它回答的是「按下建立會發生什麼」。
- 警告與那顆改日期的按鈕一起拿掉了。

### 中間那幾期不建立資料列

第 1、2 期的實際利息與當時的牌告利率**都不在帳本裡**，憑空生出兩筆空紀錄就是捏造
事實 —— 那正是這個專案在 `deposit_terms` 上一貫的立場（續存不改寫舊的一期，
就是為了讓歷次利率留得下來；補一筆沒有利率的期把那個保證變成謊）。

**跳號是誠實的，補號不是。** 第一期是 3 號，看得出這份定存滾過兩輪。

### 三個日期，三件事

這一版之後定存有三個日期，很容易混：

| | 是什麼 | 誰決定 |
|---|---|---|
| `deposit_contracts.opened_on` | **存單**上首次存入那一天 | 使用者照紙填 |
| `deposit_contracts.recorded_on` | **帳本**開始追蹤的那一天 | 預設今天 |
| `deposit_terms.start_date` | **這一期**的起存日 | `current_term()` 算 |

`recorded_on` 一個欄位兩個用途，而且兩者同義：它是產生待確認項目的下界，也是
「算滾到第幾期」的那個當下 —— 問的都是「你把它記進帳本的那一天」。

### 本息續存的本金程式不猜

「本息無限次數自動轉期續存」每一期的本金都含前一期的利息，滾過幾輪之後早就不是
存單上那個數字 —— 而程式**算不出來**（各期實際利息不在帳本裡）。所以只提醒
「本金請填目前存摺上的金額」，不試算。同 REQ-0007 §邊界 對違約息的處置。

## 順帶修掉的三件事

查證這個問題時實測出來的，都不是這份 ADR 的主題但同一批改掉：

| | 症狀 |
|---|---|
| **存本取息到期利息重複算** | 每月領息已經把整年的利息發完了，到期事件卻又建議整期總額 —— 照建議值確認，帳上的利息是實際的兩倍 |
| **零存整付到期本金是 0** | `principal_minor` 一開始就是 0，本金是每月存入累積出來的，而到期直接轉 `principal_minor` |
| **略過到期會讓那一期永遠卡住** | `UNIQUE (term_id, event_type, due_date)` ＋ `INSERT OR IGNORE`，略過掉的事件永遠不會再生出來 |

三件都有自己的測試，見 `tests/integration/test_deposits.py`。
