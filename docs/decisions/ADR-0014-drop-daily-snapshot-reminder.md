# ADR-0014：拿掉「今天還沒盤點」，只留「盤點過了、金額對不上」

- 狀態：**已接受**
- 日期：2026-09-06
- 取代：無。**與 [ADR-0011](ADR-0011-drop-recurring-schedules.md) 同向** ——
  那份拿掉了依日曆產生的待確認草稿，這一份拿掉最後一則依日曆觸發的提醒。

## 背景

資產總覽的「待辦」區本來有三列：待確認筆數、**今天還沒盤點**、未解釋差額。
中間那一列由 `settings.balance_snapshot_reminder`（預設開）控制，
條件是「預設帳戶今天沒有有效的餘額盤點」。

**它的觸發條件是日曆，不是事實。** 只要日期換了、而你今天還沒盤點，它就跳 ——
不管帳到底對不對得上。

而**餘額盤點是一個不定期的動作**：它要存摺或網銀在手邊才做得了，
不是每天坐到電腦前就能完成的事。對一個不定期的動作用日曆當觸發條件，
結果是**它每天都在說一件不需要處理的事**，然後被學會忽略。

一則永遠都在的提醒等於沒有提醒 —— 這與 ADR-0011 對定期收支的判斷是同一句話，
只是那次判斷的是「產生草稿」，這次判斷的是「顯示一行字」。

### 另外兩則提醒為什麼留著

它們的觸發條件**都是外部事實**，不是日期：

| 提醒 | 憑什麼跳 |
|---|---|
| 待確認筆數 | 定存到期／領息 —— **銀行那一端自己會動的錢，沒有人會通知你**（ADR-0011）|
| 未解釋差額 | 帳面與你數出來的金額**對不起來**。那是真的有事情要做 |

「今天還沒盤點」兩者都不是。它唯一知道的事情是「今天的日期跟上一次盤點不同」。

## 決定

**整個移除那則提醒與它的設定。**

| 拿掉的東西 | |
|---|---|
| 設定 | `ApplicationSettings.balance_snapshot_reminder`；`settings` 表那一列由 `migrate_v11` DELETE |
| application | `BalanceSnapshotService.reminder_due()` |
| store | `LedgerStore.has_balance_snapshot_on_date()` |
| controller | `refresh_balance_snapshot_reminder_due()`、`overview_snapshot()` 的 `snapshot_due_account` |
| UI | 資產總覽的 `snapshot_note`／`_show_snapshot_due()`、一般設定的「餘額盤點提醒」核取方塊 |

### 「去盤點」那顆按鈕改掛在未解釋差額上

它本來是「今天還沒盤點」那一列的按鈕，跟著那一列一起消失的話，
`balance_requested` 這個訊號就沒有人發了 —— 而**沒有人發的訊號跟沒有人 import
的 re-export 一樣，不會有任何測試提醒你它過期**（見 `../lessons.md`）。

所以它搬到未解釋差額那一列（`gap_button`）。留下來的那則提醒是真的有事情要做的，
它**配得上**一顆按鈕。同時差額那句話裡的「可到『餘額盤點』補記交易」拿掉了 ——
旁邊那顆按鈕就是那句話。

## 被否決的替代方案

| 方案 | 為什麼否決 |
|---|---|
| **保留，但預設關掉** | 一個預設關掉的開關，等於多一個沒有人會打開的選項，而維護成本一項都沒少：設定頁一列、一個 key、一條讀寫路徑、幾條測試 |
| **改成每週提醒一次** | 週期還是日曆。**不定期就是不定期**，換頻率只是把同一種噪音降頻 |
| **只從 UI 拿掉，設定與服務留著** | 違反這個專案「不留死程式」的紀律。而且 `settings` 是 key/value 表，留著那一列不會壞任何東西 —— 正因為不會壞，所以永遠不會有人發現它已經沒有人讀了 |
| **連未解釋差額那則一起拿掉** | 那則是事實觸發的，而且它正是餘額盤點這整個功能存在的理由 |

## 後果

- **好的**：待辦區從三列變兩列；一般設定少一個選項；資產總覽每次重整少一次
  「今天有沒有盤點過」的查詢。
- **壞的**：真的想要「提醒我去盤點」的時候沒有東西可用。使用者知情且接受 ——
  他的觸發點是手上有沒有存摺，不是程式。
- **沒有差額的時候，資產總覽就沒有通往餘額盤點頁的按鈕了**，要走側邊欄。
  這是刻意的：沒有事情要做的時候，不該有一顆叫你去做事的按鈕。
- **要改變這個取捨就新增一份 ADR 推翻這一份。** migration 不能 un-delete ——
  真的要加回來，是新增 `migrate_v12` 把那個 key 插回去，不是改 `migrate_v11`。

## 什麼情況下這份 ADR 該被推翻

**盤點的節奏變成規律的。** 例如使用者改成「每月 1 號對一次帳」——
那時日曆才真的對得上事實，提醒才會指向一件該做的事。

判準是**節奏，不是頻率**：一個「我想起來就做」的動作，不管提醒設多久跳一次都是錯的。
