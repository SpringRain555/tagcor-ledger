# ADR-0005 法規庫唯讀且離線

## 狀態

已接受（2026-08-18）。

## 決策

法規參考庫放在專案底下的獨立 `reference.sqlite3`，App 以 `mode=ro` **唯讀**開啟。
抓取由專案外的工具（`tools/fetch.py`，research runtime 執行）完成，
產出帶出處的 Markdown corpus 再匯入。**App 本身永遠不發網路請求。**

## 理由

「純本機、完全不連網」是本專案的核心不變量。直接在 App 裡加爬蟲會打破它 ——
一個會發網路請求的記帳程式，跟一個不會的，在信任模型上是兩種東西。

法規是**公開資訊**，不是個人資料，所以放專案底下（而不是資料根目錄）是對的：
它可以進版控、可以被審閱、可以整批重建，而且不會把帳務備份撐大。

寫進獨立資料庫而不是 `ledger.sqlite3`，是因為兩者的生命週期完全不同：
法規會整批重抓重建，帳務資料一個位元組都不能掉。綁在一起會讓每次更新法規都動到主資料庫，
而且 schema migration 兩件事綁死。

## 後果

- 更新法規是**手動的兩步**：跑抓取工具，再跑匯入。沒有自動更新。
- `reference.sqlite3` 是產生物，不進版控；進版控的是文字 corpus。
- 法規庫不存在時 App 必須正常啟動，法規頁顯示提示而不是崩潰。
- 抓取工具的依賴（`httpx`、`trafilatura`）**不進** `environment.yaml`，
  否則 App 的環境就有了網路能力。
