# 用詞對照表

**本檔的權威範圍：** 介面上、文件裡、程式碼裡各自該用什麼字。

用詞不一致的代價不是難看，是**誤解**。同一個東西在介面叫「細項」、在文件叫「子分類」、
在程式叫 `subcategory`，三個月後就會有人以為那是三個不同的東西。

**「不要叫成什麼」那一欄是重點。** 那些通常是曾經用過、後來統一掉的舊名字，
或是同類產品用但本專案刻意不用的字。

---

## 記帳的基本單位

| 中文 | 程式識別字 | 是什麼 | **不要叫成** |
|---|---|---|---|
| **帳戶** | `account` | 錢實際存放的地方。目前是郵局活儲、郵局定存、現金 | 錢包、戶頭 |
| **類別** | `category`（`level = 1`） | 分類的**第一層**。例如「伙食」「交通」 | 分類、大類、主分類 |
| **項目** | `category`（`level = 2`） | 分類的**第二層**，掛在某個類別底下。例如「7-11」「電子票證儲值」 | 細項、子分類、subcategory |
| **流向** | `entry_type` | 這筆是收入、支出還是轉帳 | 類型、方向、收支別 |
| **交易** | `transaction` | 一筆帳。是使用者看得到的單位 | 紀錄、明細、流水 |
| **posting** | `posting` | 交易對某個帳戶的實際增減。**使用者看不到這個詞** | — |
| **期初餘額** | `opening_balance_minor` | 開始記帳那一刻，這個帳戶裡本來就有多少錢 | 初始金額、起始餘額 |

> **`類別` 與 `項目` 在資料庫裡是同一張表**，靠 `level` 與 `parent_id` 區分。
> 這是刻意的 —— 兩層用同一張表，UI 用不同的字，使用者不需要知道底下是同一種東西。

## 操作

| 中文 | 程式識別字 | 是什麼 | **不要叫成** |
|---|---|---|---|
| **作廢** | `void` | 讓一筆交易不再計入，但**保留紀錄**。單向，不可復原 | 刪除、取消 |
| **封存** | `archive` | 讓帳戶或類別不再出現在選單，但歷史資料照常指向它。可恢復 | 停用、隱藏、關閉 |
| **恢復** | `restore` | 把封存的東西放回選單 | 啟用、還原 |
| **刪除** | `delete` | 真的移除。**只允許從未被任何歷史資料引用過的** | — |
| **替換轉帳** | `replace_transfer` | 改轉帳的唯一方式：建新的、作廢舊的，同一個 SQLite transaction 完成 | 編輯轉帳、修改轉帳 |
| **還原** | `restore_backup` | 從備份把整個資料庫救回來 | 回復、復原 |
| **重製** | `reset` | 把資料庫清空重來，**備份不會被刪** | 重設、初始化、清除 |

> **「恢復」與「還原」是兩件完全不同的事**，一個是把封存的類別放回選單，一個是從備份救回整個資料庫。
> 這兩個詞很容易混，UI 上務必保持這個區分。

## 對帳相關

| 中文 | 程式識別字 | 是什麼 | **不要叫成** |
|---|---|---|---|
| **餘額盤點** | `balance_snapshot` | 在某個時間點記下「實際數出來有多少錢」的快照。**不是交易，不改變餘額** | 對帳、調整、結算 |
| **預期金額** | — | 上次盤點金額 ＋ 兩次之間的有效 posting 加總 | 帳面金額、應有金額 |
| **未解釋差額** | `gap` | 本次實際金額 － 預期金額 | 誤差、落差、缺口 |
| **待確認** | `occurrence` (`pending`) | 排程產生的草稿，**還不是交易** | 待辦、預定、排程項目 |

> **盤點不是對帳。** 盤點只能對總額；對帳是逐筆核對存摺。本專案目前只有前者，
> 差別與缺口寫在 `state-machines.md` §4 與 `REQ-0010`。

## 刻意不存在的詞

這些是**曾經有過、已經移除**，或**同類產品有但本專案不做**的東西。看到它們出現在新程式碼裡就是錯的。

| 詞 | 為什麼不存在 |
|---|---|
| **對象／商家／payee** | Phase 4 移除。用「項目」描述具體收支，用「備註」補充。**不得重新加入** payee model、`payees` 表或 payee UI |
| **預算 / budget** | 不做。roadmap 明列為延後項目 |
| **標籤 / tag** | 不做。兩層分類加備註已足夠，理由見 `docs/research/market-scan.md` P1 |
| **悠遊卡帳戶 / 一卡通帳戶** | **刻意不做。** 電子票證只記儲值當下的支出，不追蹤卡內餘額。市面產品多半相反，理由見 market-scan P8 |
| **自動記帳 / 載具匯入 / 銀行同步** | **刻意不做。** 手動輸入才讓使用者感受到花費的程度，這是專案存在的理由 |
| **分類 / 細項** | 舊名。統一為 **類別 / 項目** |

## 寫程式時

- **識別字用英文**，介面文字、錯誤訊息、註解、文件用**繁體中文**。
- 中文一律繁體，不得混簡體。`tests/unit/test_traditional_chinese.py` 會擋。
- 錯誤碼是**穩定的英文大寫識別字**，不隨訊息改動。清單見 `error-codes.md`。

## 定存（Stage 5 新增）

| 中文 | 程式識別字 | 是什麼 | 不要叫成 |
|---|---|---|---|
| 定存合約 | `deposit_contract` | 持續性的定存關係：哪個帳戶、怎麼計息、到期怎麼處理 | 不要叫「定存單」—— 單據是每一期的事 |
| 期 | `deposit_term` | 定存的**一期**。續存會產生新的一期，舊的不改寫 | 不要叫「續約紀錄」；第一期也是期 |
| 計息方式 | `interest_method` | 整存整付／存本取息／零存整付 | 不要叫「存款類型」 |
| 到期轉存方式 | `maturity_action` | 到期那天本金與利息各去哪裡 | 不要叫「自動續約」—— 有四種，只有兩種會續 |
| 年利率 | `annual_rate_ppm` | **百萬分之一為單位的整數**。1.6% 是 `16000` | 不要存成小數或百分比字串 |
| 建議利息 | `suggested_amount_minor` | 程式試算的值，**不是權威值** | 不要叫「應得利息」—— 以存摺為準 |
| 定存事件 | `deposit_event` | 等待使用者確認的到期或領息 | 不要叫「排程」—— 它不走 `recurring_schedules` |
