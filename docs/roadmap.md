## 使用者提出的 UI 項目（兩項都已完成）

**2026-08-18 實機試用後提出**，七個 Stage 收工後處理，2026-08-20 全部完成。

### ~~UI-1：時間欄位要能用時鐘子視窗選~~ ✅ 2026-08-20 以「不做時鐘」收掉（v0.13.0）

原本要做彈出式時鐘選擇器。實際討論後改成**把時分欄位整個拿掉** —— 記帳需要的精度
就是「哪一天」，午餐是 12:07 還是 12:31 不會影響任何一個數字。

所以三個輸入點（快速記帳、餘額盤點、交易編輯對話框）都換成只有日曆的 `date_field()`。
資料庫仍然存完整時間戳，時分秒由程式補：新建補現在（保住同一天的先後順序）、
編輯沿用原值（改備註不該讓那筆跳到當天最後）。顯示只到日。

**沒有比較快的時鐘選擇器，只有不需要按的欄位。**

### ~~UI-2：配色重做~~ ✅ 2026-08-19 完成（v0.12.0）

深藍換成**中性純灰**，彩色只留給金額與警示。方向由使用者在四個問題裡定案：
固定深色 ／ 零色偏灰 ／ 幾乎不用彩色 ／ 支出紅收入綠。色票集中在 `ui/colors.py`，
每個組合的 WCAG 對比都算過並有測試守著。

## UI 結構重整（v0.14.0，六個 Stage 全部完成）

**2026-08-20 實機再次檢視後開工，同日收工。** 程式本身沒問題（179 個測試全綠、分層有 AST 守門、
金額不碰浮點數），八個症狀集中在 UI，而且成因是同一個：**這個專案從來沒有寫下
「一頁是什麼、什麼東西該放在哪一頁」**。每一頁各自發明版面；分組標題沒地方放就塞進
清單裡假裝成不能點的項目；沒有「這一頁回答什麼問題」的成文說明，所以連作者自己都會
忘記「待確認」是做什麼的。

另外有兩件不是風格問題的事：**有子項目的類別完全無法被選取**（改名、封存、刪除對類別
全部失效），以及**導覽用顯示文字當 key**（改一個字就是執行時的 `KeyError`）。

| Stage | 內容 | 狀態 |
|---|---|---|
| 1 | `PageId` 導覽識別、側邊欄重做（無分組標題、設定沉底）、快速記帳→記帳 | ✅ 完成 |
| 2 | 版面規則：內容置中加寬度上限、短表格收到欄寬、視窗記住大小 | ✅ 完成 |
| 3 | 帳戶餘額改單一查詢（修 N+1）、新增「資產總覽」為第一頁 | ✅ 完成 |
| 4 | 類別／項目修復，操作設定拆成六個分頁 | ✅ 完成 |
| 5 | 待確認併成單一收件匣（定期收支與定存同一張表） | ✅ 完成 |
| 6 | 用詞、文件、漂移守門、版本升到 0.14.0 | ✅ 完成 |

已定案的決定：

- **側邊欄不放分組標題。** 分組靠位置：日常在上、設定沉底。**側邊欄裡的每一個字都可以點。**
  （這條路用「程度差異」試過兩次都失敗 —— 見 [失敗紀錄](lessons.md)。）
- **操作設定拆成六個分頁**：帳戶／類別／項目／模板／定期收支／定存。
- **「週期排程」UI 上改叫「定期收支」**；程式識別字 `recurring_schedules`、`schedule_id`
  不動（那是 schema，改它要 migration，而使用者看不到它）。
- **定存維持叫「定存」**，不改叫「郵局定存」；**不與定期收支合併** —— 一個是「每 N 個月
  重複同一筆」、一個是「一期一期滾、有利率與到期轉存方式」，合併會做出一個裝兩種表單的分頁。
- **待確認併成一張表**加「來源」欄，六顆按鈕減到三顆，空的時候整頁說明自己是做什麼的。

**收工時的狀態**：222 passed ＋ 1 skipped（20 萬筆的效能測試要設環境變數才跑），
ruff 與 mypy --strict 乾淨。
成因的解法是 [ui-workflows 的頁面地圖](architecture/ui-workflows.md#頁面地圖)
（每一頁：它回答什麼問題／什麼時候用／**不在這裡做的事**），由
`tests/unit/test_docs_drift.py` 逐字守著，改了頁名而沒改文件會紅。

**這一輪學到最貴的一件事：測試全綠不等於畫面是對的。** 六個 Stage 裡有四個毛病
只有截實機的圖才看得到，而且發現了一條從加進來那天起就沒有檢查過任何東西的守門
（用 `isVisible()` 過濾，`QStackedWidget` 底下的頁在 offscreen 永遠回報 `False`）。
三筆都記在 [失敗紀錄](lessons.md)。
