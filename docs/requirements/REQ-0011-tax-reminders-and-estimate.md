# REQ-0011 稅務：提醒、判斷與試算

狀態：**規格已定，實作中**（2026-11-09 起，分支 `wip/tax-system`）

> 決定的理由不在這裡：依法定期間觸發的提醒見 [ADR-0019](../decisions/ADR-0019-statutory-tax-reminders.md)，
> App 試算綜所稅見 [ADR-0020](../decisions/ADR-0020-income-tax-estimate.md)。這一份只寫**做什麼、做到哪、怎麼驗收**。
>
> 與既有規格的關係：
> - **推翻 [REQ-0008](REQ-0008-reference-db.md) 的「App 不計算稅額」**，範圍僅限本文定義的綜所稅試算（ADR-0020）。
>   「不做申報、不依法規自動調整任何帳務數字」照舊成立。
> - REQ-0008 寫了卻一直沒做的「每年 5 月報稅季前提示全面複查」由本文 §資料新鮮度 實作。
> - 法規參考庫本身（corpus、`reference.sqlite3`、唯讀開啟）不變，只是它的頁面變成「稅務」頁的一個分頁。

## 目標

稅務從「查得到條文」變成**有實際作用**：

1. 繳稅或申報期間快到、正在進行、剛過期限時，開程式就在資產總覽看到，並知道**依帳本判斷要不要處理**。
2. 綜所稅申報季，依帳本與使用者填的申報狀況**估計應補或應退多少**；算不準的情況明說不算。
3. 定存利息被扣繳與扣補充保費時，待確認的建議金額就是**預期入帳的淨額**，扣掉的錢記下來供試算用。
4. 稅務數字會過期（每年公告、期限會順延），**過期時總覽提醒更新**；更新由使用者開 LLM session 照手冊做，
   App 本身永遠不連網、不接 LLM。

## 範圍

### 提醒的稅目（封閉集合，識別字即程式裡的 `TaxKind`）

| `TaxKind` | 名稱 | 申報還是繳納 | 典型期間（實際以 dataset 為準） |
|---|---|---|---|
| `income_tax` | 綜合所得稅 | 申報（含繳納） | 5/1–5/31，申報**去年度**的所得 |
| `house_tax` | 房屋稅 | 繳納 | 5/1–5/31 |
| `land_value_tax` | 地價稅 | 繳納 | 11/1–11/30 |
| `vehicle_license_tax` | 使用牌照稅 | 繳納 | 4/1–4/30 |
| `fuel_fee` | 公路使用養護安全管理費（原燃料費） | 繳納 | 7/1–7/31（自用車及機車） |

**燃料費 2026 年改名**：《汽車燃料使用費徵收及分配辦法》115-05-21 修正名稱及全文（交通部交運字第 1155005949 號令），
現名《公路使用養護安全管理費徵收及分配辦法》；第 6 條「自用車及機車於每年七月一次徵收」，開徵前公告起迄日期。
識別字 `fuel_fee` 沿用（內部鍵，不跟著法規名稱改），畫面顯示現行名稱。

存款利息的扣繳與補充保費**不是提醒**，是定存待確認的建議金額與試算的輸入（§存款利息）。

### 所得類別（封閉集合，所得歸類下拉選單的 10 個選項）

| `IncomeKind` | 名稱 | 試算怎麼處理 |
|---|---|---|
| `salary` | 薪資所得（含工讀、勞僱型助理） | 減 min(薪資, 薪資所得特別扣除額上限) 後併入 |
| `interest_taxable` | 利息所得（應稅，例：定存） | 併入；另減 min(利息, 儲蓄投資特別扣除額上限) |
| `interest_exempt` | 利息（免稅：郵政存簿儲金） | 不併入，列一行說明 |
| `prize` | 競技競賽及機會中獎獎金 | 全額併入；扣繳稅額算已扣繳 |
| `writing_lecture` | 稿費、講演鐘點費 | 全年合計 ≤ 免稅上限（18 萬）全數免稅；**超過就拒算** |
| `exempt_income` | 免稅所得（獎學金、學習型助學金等，依使用者判斷） | 不併入，列一行說明「依你的歸類」 |
| `foreign_income` | 海外所得（例：國外平台的競賽獎金） | 不併入綜所稅；全年 ≥ 門檻（100 萬）拒算 |
| `other_income` | 其他所得 | 全額併入 |
| `excluded` | 不計入（不是所得：初始金額、他人轉入、退稅、轉帳；或分離課稅已完稅，例：統一發票中獎） | 不併入 |
| `unsupported` | 不支援（股利、租賃、財產交易…） | 該年有任何一筆就拒算 |

另有一個算出來的桶：**未歸類**（類別與項目都沒有對應）。該年有任何一筆未歸類收入，試算拒算。

| 東西 | 位置 | 進版控 | 誰寫 | 誰讀 |
|---|---|---|---|---|
| 稅務數字＋出處 id | `reference/tax/dataset.json` | 是 | LLM session 照手冊（使用者核准後 commit） | App（唯讀）、`tools/tax_data/validate.py`、問答 session |

| 使用者的歸類、提醒開關與標記、申報狀況、扣繳憑單數字、財政部結果 | 帳本 SQLite（資料根的 `ledger\`） | **否**（私人） | **只有 App** | App；備份照舊涵蓋 |

**稅務數字只住 `dataset.json`。** 程式裡不得寫死任何年度金額、比率或期限；程式只認**規則的形狀**
（哪些欄位、怎麼比較、怎麼進位）。法規 corpus 只收 `law.moj.gov.tw` 的條文（`test_reference_library.py` 守著），
財政部、健保署、地方稅務局、公路主管機關的公告進 dataset，不進 corpus。

### 公開：`reference/tax/dataset.json` 的格式（本節是格式的權威）

UTF-8、**無 BOM**、繁體中文。金額一律整數元；比率一律 **ppm 整數**（10% = `100000`、2.11% = `21100`，沿用
`annual_rate_ppm` 的慣例）。**沒有任何浮點數。**

```json
{
  "schema_version": 1,
  "reviewed_at": "2026-12-16",
  "next_review_on": "2027-04-01",
  "notes": ["自由文字，給下一個更新的人看"],
  "sources": [
    {"id": "mof-115-amounts", "title": "財政部公告 115 年度綜所稅免稅額等", "publisher": "財政部",
     "url": "https://...", "published_on": "2025-11-27",
     "sha256": "<64 個小寫十六進位>", "fetched_at": "2026-11-20T03:00:00Z"}
  ],
  "calendar": {
    "typical": {
      "income_tax": {"start": "05-01", "end": "05-31", "basis": "所得稅法第 71 條", "source_ids": ["law-income-tax-71"]}
    },
    "years": {
      "2026": {
        "income_tax": {"start": "2026-05-01", "end": "2026-06-01", "note": "5/31 是星期日，順延到 6/1", "source_ids": ["..."]}
      }
    }
  },
  "income_tax": {
    "2025": {
      "exemption":                     {"value": 0, "source_ids": ["..."]},
      "exemption_70_plus":             {"value": 0, "source_ids": ["..."]},
      "standard_deduction_single":     {"value": 0, "source_ids": ["..."]},
      "salary_special_deduction_cap":  {"value": 0, "source_ids": ["..."]},
      "savings_investment_cap":        {"value": 0, "source_ids": ["..."]},
      "writing_lecture_exemption_cap": {"value": 0, "source_ids": ["..."]},
      "foreign_income_amt_threshold":  {"value": 0, "source_ids": ["..."]},
      "amt_basic_exemption":           {"value": 0, "source_ids": ["..."]},
      "brackets": {
        "rows": [
          {"up_to": 590000, "rate_ppm": 50000, "progressive_difference": 0},
          {"up_to": null, "rate_ppm": 400000, "progressive_difference": 911700}
        ],
        "source_ids": ["..."]
      },
      "tax_rounding": {"value": "half_up", "source_ids": ["..."]}
    }
  },
  "basic_living_expense": {
    "2025": {"value": 0, "source_ids": ["..."]}
  },
  "interest_withholding": [
    {"effective_from": "2010-01-01", "rate_ppm": 100000, "exempt_if_tax_at_most": 2000,
     "rounding": "floor", "source_ids": ["..."]}
  ],
  "nhi_supplementary_premium": [
    {"effective_from": "2021-01-01", "rate_ppm": 21100, "threshold_at_least": 20000,
     "base_cap": 10000000, "rounding": "half_up", "source_ids": ["..."]}
  ]
}
```

（上面的 `0` 與 `...` 是格式示意，不是真值。）

- `calendar.years` 的鍵是**期間所在的西元年**：`calendar.years["2026"].income_tax` 是 2026 年 5 月申報 2025 年度（民國 114 年度）的那一期。
- `income_tax` 與 `basic_living_expense` 的鍵是**所得年度**（西元）：`income_tax["2025"]` 是民國 114 年度。
- **基本生活費是另一條序列，因為公告時程差一年**：所得年度 X 的免稅額、扣除額、級距，財政部在 **X−1 年** 11 月底公告；
  X 的基本生活費要到 **X 年** 11 月底才公告（納稅者權利保護法第 4 條，依主計總處前一年的每人可支配所得中位數）。
  放在同一個 `income_tax[X]` 裡，X 年度的參數就會大半年都不齊，而那段時間根本沒有東西可以補（2026-11-09 查證：
  114 年度的基本生活費與 115 年度的免稅額等都是 2025-11-27 公告）。
- `typical` 是法定的典型期間、**不含假日順延**；`years` 是公告過的實際期間。順延只會延後截止，所以用典型期間當預估永遠偏安全。
- 規則清單（`interest_withholding`、`nhi_supplementary_premium`）依 `effective_from` 取「那一天適用的那一條」。
- **每個欄位都要寫出來，沒有值就寫 `null`、不要省略。** 可以是 `null` 的只有：`reviewed_at`、`next_review_on`、
  `sources[].published_on`、`calendar.years` 各期間的 `note`、級距最後一列的 `up_to`。

**驗證規則**（App 載入時與 `validate.py` 都跑同一份；任何一條不過 → 整份視為格式錯）：

1. `schema_version == 1`；日期都是合法 ISO 日期；`reviewed_at` 為 `null` 表示尚未建立（骨架）；
   `reviewed_at` 有值時 `next_review_on` 也要有值、而且晚於 `reviewed_at`（漏寫的話 App 永遠不會再提醒複查）。
2. `sources[].id` 唯一且符合 `^[a-z0-9][a-z0-9-]*$`；`url` 是 https；`sha256` 是 64 個小寫十六進位。
3. 每個被引用的 source id 都存在；**沒有沒被引用的 source**；每個值物件的 `source_ids` 非空。
4. `typical` 是合法 `MM-DD` 且 start ≤ end（不跨年）；`years` 的鍵是四位數年份、日期落在該年內、start ≤ end；稅目只能是上表五種。
5. 金額是整數（**拒絕布林值**）且 ≥ 0；`rate_ppm` 是整數且 0 < `rate_ppm` < 1,000,000（稅率不會是 0 或 100% 以上，
   10% 多打一個 0 就會被抓到）；`exemption_70_plus` ≥ `exemption`；`basic_living_expense` 是物件（可以是 `{}`）、鍵是四位數所得年度、
   每個值照金額與 `source_ids` 的規則。
6. 級距：至少 2 列；`up_to` 嚴格遞增、最後一列是 `null`；`rate_ppm` 嚴格遞增；第一列累進差額為 0；
   第 i 列累進差額 = 第 i−1 列累進差額 + 第 i−1 列 `up_to` ×（第 i 列 − 第 i−1 列 `rate_ppm`）÷ 1,000,000，**必須整除且相等**
   —— 抄錯一個數字就會被抓到。
7. 規則清單依 `effective_from` 嚴格遞增；`rounding` ∈ {`floor`, `half_up`}；`base_cap` > `threshold_at_least`。
8. **只有 `validate.py` 檢查**（App 不讀 manifest）：每個 source 的 `url` 在 `manifest.jsonl` 裡最新的那一筆紀錄，
   狀態必須是 200、`sha256` 必須相同。

**比率的套用**（程式裡唯一的一份）：`apply_rate(金額, rate_ppm, 進位)` ＝ 金額 × rate_ppm ÷ 1,000,000，
`floor` 無條件捨去、`half_up` 四捨五入，全程整數運算。

### 私人：帳本 schema v14

DDL 與欄位細節的權威是 [資料模型](../architecture/data-model.md)；這裡只講每張表存什麼、為什麼這樣切。

| 表／欄位 | 存什麼 | 為什麼 |
|---|---|---|
| `tax_category_mappings` | 類別或項目 × 收支（`income`／`expense`）→ 所得類別或繳款稅目 | 類別沒有收支屬性，同一個項目可能收支都用到（例：「轉帳」底下的他人轉入與轉出給他人）。**`ON DELETE CASCADE`**：對應是類別的屬性、不是歷史；能不能刪類別仍由 `delete_category` 照舊把關 |
| `tax_reminder_marks` | 稅目 × 期間年 → 已處理／本年不適用 | 手動結案只管當年 |
| `tax_year_inputs` | 所得年度 → 申報方式、扣除方式、其他特別扣除有無、受扶養人有無所得、本人 70 歲以上、受扶養人數與其中 70 歲以上、財政部結果（對答案） | 1～5 月填的是去年度，同時活在今年；放全域設定會讓去年度的試算跟著今年的答案變 |
| `tax_year_overrides` | 所得年度 × 所得類別（限 `salary`／`interest_taxable`／`prize`／`writing_lecture`）→ 扣繳憑單的給付總額、扣繳稅額 | 帳本記的是實領淨額；這四類有扣繳憑單可以抄 |
| `deposit_events.withheld_tax_minor`、`nhi_premium_minor` | 那一次領息被扣的所得稅與補充保費（`NULL`＝沒記錄，當 0） | 試算要把利息還原成毛額、把扣繳算成已扣繳 |
| 設定鍵 `tax_reminder.<稅目>` | `on`／`off`（封閉名單，比照 `sort_spec.<page>`） | 沒有這個鍵時：綜所稅＝開，其餘四項＝**未設定** |

稽核一律走 `StoreBase._audit`，**只記欄位名稱，不記金額**。

**所得類別的查法**：一筆收入的類別是「項目自己的對應，沒有就用它的類別的對應」（`COALESCE(項目, 類別)`）。
項目移到別的類別底下時，自己的對應跟著走、沿用的部分改沿用新類別。封存的類別仍然有效（歷史收入還是要歸類）。

## 提醒

### 期間從哪裡來

對稅目 k、期間年 Y：`calendar.years[Y][k]` 有就用它（**公告**）；沒有就用 `calendar.typical[k]` 套上 Y（**預估**）；
兩者都沒有 → `NO_WINDOW`（不提醒，資料狀態分頁列出來）。

- 開始提醒日 `notify_from` ＝ 開始日 − 14 天；過期仍提醒到 `overdue_until` ＝ 截止日 + 30 天。
- 今天屬於哪一個週期：在 Y−1、Y、Y+1 三個週期裡找 `[notify_from, overdue_until]` 含今天的那一個；都沒有就取下一個未來的週期（`DORMANT`）。

### 狀態（每次現算，**只存標記與開關**）

優先順序由高到低：

| 狀態 | 條件 |
|---|---|
| `DISABLED` | 開關是 `off` |
| `UNSET` | 沒設定過（綜所稅不會有這個狀態） |
| `NO_WINDOW` | dataset 沒有這個稅目的期間 |
| `HANDLED`／`NOT_APPLICABLE` | 這個週期有手動標記 |
| `PAID` | 在 `[notify_from, min(今天, overdue_until)]` 之間有一筆支出，其類別（項目優先）對應到這個稅目 |
| `DORMANT` | 今天 < `notify_from` |
| `UPCOMING` | `notify_from` ≤ 今天 < 開始日 |
| `OPEN` | 開始日 ≤ 今天 ≤ 截止日 |
| `OVERDUE` | 截止日 < 今天 ≤ `overdue_until` |

- 總覽只顯示 `UPCOMING`／`OPEN`／`OVERDUE`。
- `PAID` 是**帳本事實結案**：繳款刪掉、改類別或拿掉對應，它就自動回到時間狀態 —— 因為狀態是現算的。
- **刻意不推論**：不算滯納金、不判斷繳款金額對不對、`notify_from` 之前的繳款不算（可能是去年的）、
  不套用假日順延到典型期間、不猜使用者有沒有房或車、綜所稅退稅（收入）不會讓提醒結案。

### 預設開關

綜所稅預設開；房屋稅、地價稅、牌照稅、燃料費預設**未設定** —— App 不知道使用者有沒有房、車，所以不猜。
未設定的稅目不提醒，但總覽有一列「還有 N 項稅務提醒沒決定要不要開。」直到每一項都設成開或關。

| 問題 | 條件 | 總覽那一句 |
|---|---|---|
| `DATASET_MISSING` | `dataset.json` 不在 | 稅務資料不在，稅務提醒與試算暫停。 |
| `DATASET_INVALID` | 讀不了或驗證不過 | 稅務資料格式有誤，稅務提醒與試算暫停。 |
| `NOT_POPULATED` | `reviewed_at` 是 `null` | 稅務資料還沒建立。 |
| `PARAMETERS_MISSING` | 缺 `income_tax[今年−1]` 或 `income_tax[今年]`（12/15 起也要 `income_tax[今年+1]`）；或缺 `basic_living_expense[今年−1]`（12/15 起也要 `basic_living_expense[今年]`）。{年} 是兩者缺的年度的聯集 | 稅務資料缺 {年} 年度的參數，該更新了。 |
| `REVIEW_DUE` | 今天 ≥ `next_review_on` | 稅務資料該複查了（預定 {日期}）。 |
| `LAW_REVIEW_DUE` | 今天在今年綜所稅期間的 [開始日 − 30 天, 截止日] 之內，且法規庫最舊的 `reviewed_at` 早於今年 1/1 | 報稅季前，法規參考庫該全面複查一次。 |

- 優先順序就是表的順序；總覽**只顯示最優先的一則**，資料狀態分頁列全部。
- `DATASET_MISSING`／`DATASET_INVALID`／`NOT_POPULATED` 時，所有提醒與試算都停（不是部分顯示）。
- 缺公告期間（只能用預估）**不是**總覽列；它在提醒列上標「（日期為預估）」，並列在資料狀態分頁。
- `LAW_REVIEW_DUE` 有意義的前提：`build_corpus.py` **不再每次重蓋 `reviewed_at`**（要明確給 `--reviewed-at`），
  `reviewed_at` 才代表「有人複查過」而不是「上次重建」。

**要貼給 LLM session 的指示**（資料狀態分頁顯示、可複製；純文字、不含 markdown 與反引號）：

```

完成條件：python tools/tax_data/validate.py --today {今天} --require-current 結束碼為 0。
```

## 綜所稅試算

### 輸入

| 輸入 | 從哪裡來 |
|---|---|
| 各所得類別該年的筆數與淨額 | 帳本 SQL：收入交易、日期在 `[所得年度-01-01, 所得年度+1-01-01)`、依 §所得類別的查法分桶 |
| 定存利息被扣的所得稅與補充保費 | 同一個查詢 `LEFT JOIN deposit_events`（狀態為已確認、`transaction_id` 指到那筆收入） |
| 申報狀況、受扶養人數、70 歲以上 | `tax_year_inputs[所得年度]`（使用者填） |
| 扣繳憑單的給付總額與扣繳稅額 | `tax_year_overrides[所得年度][類別]`（使用者填，空白＝用帳本） |
| 免稅額、扣除額上限、門檻、級距、進位 | `dataset.income_tax[所得年度]` |
| 基本生活費 | `dataset.basic_living_expense[所得年度]`（當年 11 月底才公告；沒有就拒算 `basic_living_pending`） |

**加總一律在 SQL 裡做**（CLAUDE.md），每個新查詢要有 `EXPLAIN QUERY PLAN` 測試。

### 計算順序（整數元，所有中間值 ≥ 0）

以下 `ov(k)` 表示 `tax_year_overrides` 裡類別 k 的那一列，`帳(k)` 表示帳本該類的淨額。

1. 薪資收入 Sg ＝ `ov(salary).給付總額` ?? `帳(salary)`；Ds ＝ min(Sg, 薪資特別扣除上限)；S ＝ Sg − Ds。
   只用帳本時加一行提醒：「帳本是實領，通常低於給付總額。」
2. 應稅利息 I ＝ `ov(interest_taxable).給付總額` ?? （`帳(interest_taxable)` ＋ 帳上記錄的扣繳稅額 ＋ 補充保費）。
3. 獎金 P ＝ `ov(prize).給付總額` ?? `帳(prize)`。
4. 稿費講演 WL ＝ `ov(writing_lecture).給付總額` ?? `帳(writing_lecture)`；WL > 免稅上限 → 拒算；否則貢獻 0。
5. 海外所得 F ＝ `帳(foreign_income)`；F ≥ 門檻 → 拒算；否則貢獻 0。
6. 其他 O ＝ `帳(other_income)`。
7. 綜合所得總額 G ＝ S ＋ I ＋ P ＋ O。
8. 人數 n ＝ 1 ＋ 受扶養人數；加成人數 s ＝ 本人 70 歲以上 ＋ 受扶養人中**免稅額增加百分之五十**的人數；
   免稅額 E ＝ (n − s) × 免稅額 ＋ s × 70 歲免稅額（加成後的金額）。
   **加成的對象隨年度變**：受扶養的直系尊親屬年滿 70 歲；**115 年度起也包括未成年的受扶養子女**
   （所得稅法第 17 條 115-09-11 修正，自 115-01-01 施行）。欄位名 `dependents_70_plus` 沿用，意思是「加成人數」；
   畫面上的說明要寫清楚，否則有未成年子女的人 115 年度起免稅額會被少算。
9. 標準扣除 Std ＝ 單身標準扣除額；儲蓄投資 Sav ＝ min(I, 儲蓄投資上限)。
10. 基本生活費差額 B ＝ max(0, `basic_living_expense[所得年度]` × n − (E ＋ Std ＋ Sav))。（其他會進這個比較基準的特別扣除都在拒算清單裡，所以基準是完整的。）
11. 所得淨額 N ＝ max(0, G − E − Std − Sav − B)；N > 最低稅負基本所得額免稅額 → 拒算。
12. 找第一個 `up_to` 為 `null` 或 N ≤ `up_to` 的級距 k；應納稅額 T ＝ max(0, apply_rate(N, rate_k, 進位) − 累進差額_k)。
13. 已扣繳 W ＝ Σ（`ov(k).扣繳稅額`，沒有就 0）for k ∈ {salary, prize, writing_lecture} ＋（`ov(interest_taxable).扣繳稅額` ?? 帳上記錄的利息扣繳）。
    **補充保費不算已扣繳。**
14. 應補（退）R ＝ T − W：R > 0 應補、R < 0 應退、R ＝ 0 不用補也沒得退。
15. 得免申報 ＝ G ≤ E ＋ Std，且 W ＝ 0（所得稅法第 71 條；有扣繳要退就還是得申報）。

### 拒算（有任何一項就**不顯示任何稅額**，全部原因都列出來）

| 原因 | 使用者能怎麼辦 |
|---|---|
| `dataset_unavailable`、`parameters_missing` | 照資料狀態分頁的指示更新資料 |
| `basic_living_pending` | 等財政部 11 月底公告那一年的基本生活費，再照手冊補資料（參數缺的時候只報 `parameters_missing`） |
| `inputs_missing` | 填這一年的申報狀況（沒填過的年度從前一年預填，**按「儲存並試算」才算**） |
| `unmapped_income` | 到所得歸類分頁把收入歸類 |
| `with_spouse`、`dependent_of_other`、`dependent_income`、`itemized_deduction`、`other_special_deductions` | 不支援，請改用財政部稅額試算 |
| `unsupported_income` | 不支援，請改用財政部稅額試算 |
| `writing_lecture_over_cap`、`foreign_income_amt`、`amt_possible` | 不支援，請改用財政部稅額試算 |

### 輸出

- 一張明細：步驟｜金額｜依據。依據是四種之一：**帳本**（N 筆）、**扣繳憑單（你填的）**、**財政部公告**（source 標題）、**計算**。
  免稅利息、免稅所得、不計入、海外所得也各列一行說明它們沒有進總額。
- 狀態行：「估計：應補 X 元」／「估計：應退 X 元」／「估計：不用補也沒得退」，加上「得免申報」時的說明；
  拒算時只列原因與「請改用財政部稅額試算」，**沒有任何數字**。
- 固定頁尾：「這是估計，不是申報；以財政部稅額試算為準；不會改動帳本任何金額。」

### 對答案

申報後在試算分頁填**財政部算出的應納稅額**（必填）與**應補（退）稅額**（選填，補為正、退為負），存進 `tax_year_inputs`。
之後那一年的試算多一行「與財政部相差 X 元」，旁邊列常見原因：用了實領而非給付總額、漏記收入、扣繳沒填、歸類錯。
拒算原因本身就是「下一版該支援什麼」的清單；手冊的年度複查會請使用者說出今年差在哪一類（**只講差在哪一行，不貼金額**），
反覆出現的原因變成規格與測試。

## 存款利息的扣繳與補充保費

對**單次**利息給付 g（依領息那一天適用的規則）：

- 所得稅扣繳：g × `rate_ppm` > `exempt_if_tax_at_most` × 1,000,000 才扣（先交叉相乘再進位，不在進位後比較），
  扣繳稅額 ＝ apply_rate(g, `rate_ppm`, `rounding`)。
- 補充保費：g ≥ `threshold_at_least` 才扣，保費 ＝ apply_rate(min(g, `base_cap`), `rate_ppm`, `rounding`)。
- 測試邊界（以「10%、免扣上限 2,000、2.11%、門檻 2 萬、上限 1,000 萬」為例）：19,999 → 0／0；20,000 → 0／422；
  20,001 → 2,000／422；兩種進位各測一次；基數上限測一次。

行為：

1. 待確認的「建議金額」改成**預期入帳淨額** ＝ 試算利息 − 扣繳 − 補充保費，旁邊附算式：
   「試算：利息 X − 扣繳 Y − 補充保費 Z ＝ 預期入帳 N。三格都以存摺為準。」
2. 確認對話框多兩格「所得稅扣繳（TWD）」「二代健保補充保費（TWD）」：預填試算值、可改、可空白；零存整付的每月存入沒有這兩格。
3. **交易金額仍是存摺上的實際入帳**（帳本照實）；兩個扣款數字存在那一筆 `deposit_events`。
4. 期的實際利率改用毛額（淨額 ＋ 兩筆扣款）推回；續存與 `actual_interest_minor` 仍是淨額。
5. `_interest_category_id()` 改成優先找「利息收入」底下名叫「定存利息」的項目，找不到才取第一個、再找不到才建 ——
   否則使用者把「活儲利息」（免稅）排在前面時，應稅的定存利息會被記進去。

## 邊界（硬性非目標）

- **App 不連網、不接 LLM、不用 RAG。** 所有計算都是確定性的：同一份 dataset ＋ 同一本帳 → 同一個結果。
- **不申報、不繳稅、不替使用者記帳；試算不改任何帳務數字。** 提醒不建立待確認草稿（ADR-0011 的取捨不變）。
- 試算不支援：配偶合併、被他人扶養、受扶養人有所得、列舉扣除、其他特別扣除、股利／租賃／財產交易、
  稿費講演超過免稅上限、海外所得達門檻、可能適用最低稅負。**一律明說拒算，不硬算。**
- 不依名稱猜歸類；不新增標籤概念（[用詞對照表](../architecture/glossary.md) 明文不做 tag）。
- 不計算滯納金、不判斷繳款金額對不對、不推論使用者有沒有房車。
- 不收整部法規全文（REQ-0008 照舊）。

## 驗收

- dataset 驗證：每條規則都有一個「該過的」與一個「該紅的」例子；級距抄錯一個數字會紅。
- 提醒：以「4/1–4/30」為例，3/17、3/18、4/1、4/30、5/1、5/30、5/31 七個日期各是什麼狀態有表格測試；
  公告優先於預估；`notify_from` 之前的繳款不結案；標記只管當年；關掉就不提醒；未設定的出現在狀態列。
- 新鮮度：每一種問題各有測試，含報稅季前後的邊界日。
- 試算：至少三組手算的黃金案例（含級距邊界 590,000 與 590,001 的連續性、受扶養人與 70 歲以上、
  基本生活費差額），每一個拒算原因各一條測試；拒算時畫面上沒有任何稅額。上線前再加 1–3 個財政部官方範例逐元重現。
- 扣繳與補充保費：上面的邊界數字全部有測試；交易金額是實際入帳淨額；毛額還原後進到試算。
- schema：v13 → v14 升級、重跑不壞、各 CHECK、`ON DELETE CASCADE`（刪掉沒用過的類別時對應一起消失；用過的類別照樣刪不掉）。
- 每個新查詢都有 `EXPLAIN QUERY PLAN` 測試。
- UI：總覽在沒有稅務事項時不出現任何稅務列；稅務列不換行；點「查看」到對的分頁；拒算時不顯示金額。
  測試的預設假資料讓總覽**不隨季節變**，要看列的測試換成「全年都是期間」的假資料。
- App 仍然不 import 任何網路函式庫（守門補上 `urllib.request`、`ssl`、`PySide6.QtNetwork` 除本機 IPC 以外的部分）。
