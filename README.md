# TagCor Ledger

TagCor Ledger 是 Windows-first、本機優先的個人記帳工具。核心資料使用 SQLite，介面使用 PySide6，目標是快速記錄收支、轉帳、餘額盤點與待確認項目，同時保持資料可備份、可還原、可長期維護。

目前版本：**0.24.1**（記帳頁照填寫順序問、表格欄寬會讓路、勾選框補回勾號）。0.24.0 讓定存照存單填就好並修掉三處計算錯誤；0.22.0–0.23.0 加了資產占比圓環、修好模板封存、移除定期收支；0.20.0–0.21.1 是一輪體質工作（controller／stores／formatting 依功能拆檔、例外收斂、補測試、pre-commit 加閘門）；0.17.0–0.19.0 讓類別與項目可以排成自己想要的順序，排序搬進獨立視窗、支援多層且記得住。

**帳務資料不在專案資料夾裡。** 程式一個位置、資料另一個位置，由「系統設定 → 資料路徑」指定，資料永遠不進版控 —— 所以這個 repo 公開的只有程式。完整說明見 [Storage layout](docs/architecture/storage-layout.md)。

## 目前功能

- 開啟即見的「資產總覽」：總資產、各帳戶餘額與**資產占比圓環**、下一筆定存到期、待辦。
- 記帳流程：流向 → 金額 → 帳戶 → 類別 → 項目 → 日期 → 備註。
- 收入、支出、同幣別 TWD 轉帳。轉帳分三種對象：我的帳戶之間、別人轉入、轉出給別人；
  **對外的兩種存成收入與支出**，總資產才會跟著動（見 [ADR-0010](docs/decisions/ADR-0010-external-transfers.md)）。
- 交易紀錄支援文字、日期、帳戶、類別與狀態篩選，使用 keyset pagination。
- 帳戶、類別、項目與模板都可新增、封存、恢復、刪除 —— **封存一律可逆**。
- 待確認項目與批次確認。
- 餘額盤點與未解釋差額追蹤；盤點不會直接入帳。
- 郵局定存：合約與每一期分開記錄，三種計息方式 × 四種到期及轉存方式
  （四個中文名逐字照存單）。到期與領息**只產生待確認項目**，由使用者確認才入帳，
  程式不會自己記帳。**填的是存單上首次存入那一天**，程式算出目前存續中的是第幾期；
  **建檔之前就到期的期數不產生項目** —— 那段歷史已經含在帳戶的期初餘額裡
  （[ADR-0012](docs/decisions/ADR-0012-deposit-events-start-at-record-date.md)）。
  另有結束合約與中途解約。
- 法規參考：6 部法規、17 條精選條文的離線查閱庫，含白話摘要與條文原文。
  **App 不連網**，法規庫是離線產生的唯讀檔案。
- 啟動失敗、資料庫被鎖、磁碟不可用等狀況會顯示繁中說明並寫入日誌，不會無聲消失。
- 電子票證（悠遊卡／一卡通／iCash）只記儲值當下的支出，**不建卡片帳戶、不追蹤卡內餘額**。
- 記帳資料路徑與備份路徑可分開設定。
- 備份只在使用者手動按下「建立完整備份」時執行。
- 還原與重製前可勾選「先建立備份」，不再強制自動備份。
- 固定深色主題，中性純灰配色；彩色只用在金額與警示。
- UTF-8 BOM CSV 匯出供交換與人工閱讀；SQLite 是唯一主資料庫。

## UI 主題

固定深色，不提供亮色／暗色切換。設計方向是**中性純灰、彩色只留給金額**：

- 底色是**零色偏的灰**（`#0D0D0F` → `#16161A` → `#1F1F25`），不是深藍也不是暖褐。
  灰階沒有色相，金額的紅綠才不會被底色帶偏。
- **介面本身幾乎沒有顏色。** 主要按鈕是近白底深字（靠明度，不靠色相），選取列是淺一階的灰，
  焦點框是中性亮灰。所以畫面上任何一抹紅或綠都一定是資訊，不是裝飾。
- **金額：支出紅、收入綠、轉帳不上色。** 顏色不是唯一線索 —— 同時有正負號（`-120` / `+842`）
  與右對齊千分位（`+36,000`），色盲、列印與截圖都讀得出來。
- 所有「文字／底色」組合的 WCAG 對比都 >= 4.5，而且是拿**選取列**（最亮的底）算的。
- 高風險操作（刪除、作廢、重製、還原）用紅色危險按鈕。
- 字體是 **Microsoft JhengHei UI 12pt Medium**。主字體用中文字型是刻意的 ——
  `Segoe UI Variable` 沒有中文字形，對它設字重只有數字會變粗，中文不會。
  fallback 順序：`Microsoft JhengHei UI`、`Microsoft JhengHei`、`Noto Sans TC`、
  `Segoe UI Variable`、`Segoe UI`、sans-serif；不額外打包字型檔。
- 色票的正本是 `src/tagcor_ledger/ui/colors.py`，QSS 不得出現清單以外的色碼（有測試擋）。

## 側邊欄

由上到下：**資產總覽、記帳、待確認、交易紀錄、餘額盤點**，然後留白，最底是
**法規參考、操作設定、系統設定**。

- **沒有分組標題，側邊欄裡的每一個字都可以點。** 分組靠位置：每天用的在上、設定貼底。
- 開啟程式停在**資產總覽** —— 打開的當下多半還沒決定要做什麼，先看狀況才合理；
  真的要記帳，`Ctrl+N` 一鍵就到。
- 待確認的筆數畫在項目右側；視窗窄於 1100 px 時側邊欄自動縮一階。

各頁分別回答什麼問題，見 [UI Workflows 的頁面地圖](docs/architecture/ui-workflows.md)。

## 安裝

建議讓 Conda 管理 PySide6/Qt，避免 Windows Qt DLL 衝突。

```powershell
conda env create -f environment.yaml
conda activate tagcor-ledger
python -m pip install -e ".[dev]"
```

如果曾用 pip 安裝 PySide6 後遇到 `ImportError: DLL load failed while importing QtWidgets`，請重建環境或執行：

```powershell
conda env update -f environment.yaml --prune
conda activate tagcor-ledger
python -m pip install -e ".[dev]"
```

## 啟動

### 一鍵啟動（建議）

**雙擊專案根目錄的 `Start TagCor Ledger.cmd`。** 不用先開終端機、不用 `conda activate`。

它會自己找到 conda 環境的直譯器（絕對路徑）、清掉繼承來的 `VIRTUAL_ENV`／`PYTHONPATH`、
跑一次前置檢查確認套件與資料路徑可用，然後開視窗。出問題時會停在畫面上說明原因與修法，
不是一閃而過。

想在桌面放捷徑：

```powershell
.\Launch.ps1 -CreateShortcut
```

conda 裝在非標準位置時，設一次環境變數即可：

```powershell
setx TAGCOR_PYTHON "X:\path\to\envs\tagcor-ledger\python.exe"
```

### 從終端機啟動

```powershell
conda activate tagcor-ledger
python -m tagcor_ledger --gui
```

> **注意：終端機裡若已經啟動了別的專案的 venv，這個做法會失敗。**
> venv 的 `Scripts` 排在 PATH 最前面，`conda activate` 之後它仍然排在前面 ——
> 兩個環境的名字都會出現在提示字元上（`(.venv) (tagcor-ledger)`），但 `python` 解析到的
> 是 venv 那一個，症狀是 `No module named tagcor_ledger`。
> 用 `(Get-Command python).Source` 可以確認實際跑的是哪一個；先 `deactivate` 或改用一鍵啟動。

開發或測試時指定資料根目錄：

```powershell
python -m tagcor_ledger --data-dir .\.local-data --init-data --gui
```

輸出啟動路徑資訊：

```powershell
python -m tagcor_ledger --data-dir .\.local-data --init-data --json
```

未指定 `--data-dir` 時，程式會使用外部系統設定檔中的路徑。可在「系統設定 → 資料路徑」設定：

- 記帳資料路徑：存放 `ledger.sqlite3`、`ledger.sqlite3-wal`、`ledger.sqlite3-shm`。
- 備份路徑：存放 `backup_YYYYMMDD_HHMMSS_xxxxxx/ledger.sqlite3` 與 `backup_manifest.json`。

備份路徑不可與記帳資料路徑相同，也不可互相包含。

## 操作方式

### 記帳

1. 選擇流向：支出、收入或轉帳。
2. 選轉帳時再選**轉帳對象**：我的帳戶之間／別人轉入／轉出給別人。
3. 選擇帳戶；支出、收入與**對外轉帳**都要選「類別」與「項目」，
   只有「我的帳戶之間」是改選轉入帳戶。
4. 填寫 TWD 整數金額、日期與備註。**日期只到「哪一天」，沒有時分欄位。**
5. 按「儲存交易」。

「項目」用來描述具體收支項目，例如早餐、捷運、7-11。備註用來補充當次交易的額外資訊。Phase 4 已移除「對象／商家」欄位。

快捷鍵：

- `Ctrl+N`：回到記帳頁並聚焦金額欄位。
- `Ctrl+S`：儲存記帳表單。
- `Esc`：清空記帳表單。

### 交易紀錄

- 可用文字、日期區間、帳戶、類別與狀態組合篩選。
- 每頁筆數由「系統設定 → 一般設定」設定為 20、50 或 100。
- 「複製到記帳」會使用目前時間，並帶入帳戶、類別/項目、金額與備註。
- 支出與收入可編輯；轉帳採「替換轉帳」：建立新轉帳並作廢舊轉帳，兩者在同一 SQLite transaction 完成。
- 作廢交易不刪除歷史資料，會保留 audit 與餘額可追蹤性。

### 餘額盤點

餘額盤點用來記錄某帳戶當下實際金額，盤點本身不會建立交易，也不會改變帳戶餘額。

差額計算規則：

- 第一筆盤點前，以帳戶期初餘額作為基準。
- 後續盤點以「上一筆有效盤點」作為基準。
- 預期金額 = 上次盤點實際金額 + 兩次盤點間有效 posting 加總。
- 未解釋差額 = 本次盤點實際金額 - 預期金額。

補記、編輯或作廢交易後，差額會依交易時間自動重新計算。

### 操作設定

「操作設定」有六個分頁，**順序本身就是分組** —— 前四個是記帳會用到的名冊，後兩個是會自己到期的東西：

- 帳戶：新增、重新命名、封存、恢復、刪除未使用。新增時名稱與期初餘額在同一張表單裡填完
  （**期初餘額可以是 0**，那也是預設值）。
- 類別：第一層。每一個類別都有自己的一列，會顯示它底下有幾個項目。
  上方可用名稱搜尋與狀態（使用中／已封存／全部）篩選，點欄位標題可排序。
- 項目：第二層。上方可用名稱搜尋、所屬類別與狀態篩選，點欄位標題可排序。
  **搜尋也吃類別名** —— 打「交通」就會列出交通底下的每一項。
  新增時「所屬類別」與「項目名稱」在同一張表單裡選完填完，按一次確定。
- **帳戶、類別、項目、模板的排序都在那一頁的「排序設定」視窗裡設**，而且**會記住**，
  下次開程式還是那個排法。視窗分兩半：
  - **左半「排序方式」**：最多三層，每層選一個欄位與升冪／降冪。第一層平手時才輪到
    第二層（例如「先照狀態、同狀態再照名稱」）。「自訂順序」也是可選的欄位之一。
  - **右半「自訂順序」**：拖曳（或上移／下移）排出自己要的順序，常用的排前面。
    **項目是兩欄**：左邊排類別、右邊排所選類別底下的項目。
  - 按「確定」才存下來，取消什麼都不做。已封存的也會列出來（標「已封存」），
    這樣以後恢復它時位置才不會亂掉。
  - 自訂順序也用在**記帳頁的下拉選單**（每天記帳會少捲一點）與**資產總覽**的帳戶列表；
    **排序方式只影響那一頁**，不會改變下拉的順序。
  - 排序方式如果沒用到「自訂順序」，視窗會提醒你拖曳的結果不會顯示在清單上。
- 模板：常用組合。**「填入記帳頁」只預填、不直接入帳**，仍要自己按儲存。
  可封存、恢復、刪除（模板沒有東西引用得到，所以永遠刪得掉）。
- 定存：定存合約與每一期，含新增、修改、刪除，以及「產生到期與領息項目」。

**封存不是刪除的前置條件**，兩者是平行的兩條出路：判準只有「有沒有被歷史資料引用過」，
使用中的帳戶只要沒被用過一樣刪得掉。被交易、盤點或模板引用過的就只能封存，
以維持帳務一致性。**模板是例外** —— 沒有任何一張表引用得到它，所以永遠刪得掉。
預設帳戶不可刪除，需先切換預設帳戶。

### 待確認

- 定存到期與領息只產生待確認項目，**不會自動入帳**。
- **確認時只問實際金額**（以存摺為準，建議值只是程式試算）。帳戶、流向與類別
  是合約當初就決定好的，要改去「操作設定 → 定存」。
- **沒有「全部確認」。** 批次套用試算值等於替你決定一個你沒看過的數字。
- 可略過單筆 —— 那是「我看過，這一期不記」，不產生交易。
- 待確認的筆數會畫在側邊欄項目右側，不必點進去才知道有沒有事情要處理。
- 產生是**啟動時做一次**；程式開著的時候剛建了合約，用
  「操作設定 → 定存 → 產生到期與領息項目」。

### 系統設定

「系統設定」包含：

- 一般設定：預設帳戶、預設流向、交易列表每頁筆數、餘額盤點提醒。
- 資料路徑：設定記帳資料路徑與備份路徑，可選「切換到既有資料」或「搬移目前資料」。
- 備份與還原：列出備份、驗證備份、還原備份、選擇外部備份資料夾、匯出 CSV。
- 重製：清空目前記帳資料，回到乾淨預設資料；**不刪除備份資料夾**。
  確認框會列出目前有多少筆資料，沒勾「先建立備份」時會明講沒有備份可以救。

備份只會在使用者手動按「建立完整備份」時建立。還原與重製前的保護備份必須由使用者勾選。

系統設定裡還有「匯出診斷資訊」：版本、schema 版本、七個路徑、`integrity_check`、各表筆數
與最近 200 行日誌。**不含任何金額、備註或帳戶名稱**，所以可以直接交出去問人。

### 法規參考

離線查閱用的稅務與金融法規庫：主題篩選、中文全文搜尋、條文詳情（白話摘要、對這個帳本的意義、
條文原文），每一條都附來源網址、修正日期與抓取時間。

- **App 永遠不連網。** 抓取是 `tools/law_sync/` 的外掛工具，手動執行，見 [reference/README.md](reference/README.md)。
- 法規庫是產生物，**不進版控**。檔案不存在時記帳完全不受影響，該頁會說明怎麼建立。
- **不計算稅額、不做申報、不依法規自動調整任何帳務數字。** 這是查閱用的參考資料，
  不是稅務或法律意見，以主管機關公告為準。

## 驗證

```powershell
.\Verify.ps1                 # 路徑漂移檢查 + Qt stub + ruff + mypy --strict + pytest
.\Verify.ps1 -Ui             # 加跑 tests\ui（offscreen）
.\Verify.ps1 -Performance    # 加跑 200,000 筆效能回歸
```

三層自動閘門，各擋不同的東西（第一次 clone 要跑一次
`git config core.hooksPath .githooks` 才會生效）：

| 層 | 何時 | 跑什麼 | 耗時 |
|---|---|---|---|
| `pre-commit` | 每次 commit | ruff ＋ mypy | 約 2 秒 |
| `pre-push` | 每次 push | ruff ＋ mypy ＋ **全部測試** | 約 70 秒 |
| GitHub Actions | push 之後 | 同上，少了量像素的 21 條 | 約 60 秒 |

`pre-push` 跑得比 CI 完整：量像素的測試（`geometry` marker）只在 Windows 上量才
有意義，而 CI 跑 Linux。要跳過任一層用 `--no-verify`。
